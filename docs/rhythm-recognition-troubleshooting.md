# 리듬게임 동작 인식 개선 기록

## 문제와 범위

박수는 손목이 조금 떨어져 인식되거나 카메라 각도에 따라 보이지 않아 놓치는 장면이 있었다. 팔꿈치를 굽혀 손을 어깨 가까이 든 경우 손 들기 판정도 놓쳤다. 동작 후보가 중복될 때 테스트 화면과 영상 CSV에서는 결과를 보류해 실험 결과를 해석하기 어려웠다.

## 변경과 확인

- 박수의 손목 거리 기준을 어깨너비의 0.65배에서 0.75배로 조정했다. 0.2초 간격으로 같은 포즈 추출 결과를 비교했을 때 `eunji_clap_temp.mp4`의 박수 이벤트는 3개에서 5개로 늘었다. `eunji_clap.mp4`는 9개로 같았고, 각각 한 개씩의 손 들기·팔 벌리기 비교 영상에서는 박수 이벤트가 0개였다. 이벤트 수는 검출 수이며 정확도나 시행 성공 횟수가 아니다.
- 손 들기는 팔꿈치 높이를 사용하지 않고 손목과 어깨의 화면상 높이를 비교한다. 차이 기준을 화면 높이의 8%에서 2%로 낮추고, 손목이 어깨 근처일 때 신뢰할 수 있는 검지 관절이 충분히 높으면 후보에 포함했다. 기존 오른손 영상 중 하나에서 이전 손목 기준으로 후보가 없었으나 변경 후 프레임별 분석에서 오른손 후보 64프레임이 나왔다. 이 영상은 좌우 반전과 파일명에 주의해야 하며, 64는 독립 시행 횟수나 정확도가 아니다.
- 테스트 API와 영상 CSV는 원래 후보를 보존한다. 팔 벌리기 또는 박수가 손 들기와 중복되면 해당 동작을 선택하고, 팔 벌리기와 박수가 동시에 나오거나 양손 들기만 중복되면 `conflict`로 보류한다. 자세 미인식과 후보 없음도 구분한다. 실험용 판정에 지시 동작 정답을 사용하지 않는다.
- 기존 게임의 횟수 계산에서 첫 프레임의 박수 이벤트가 무시되지 않도록 초기 상태를 수정했다. 기존 서비스 게임의 동작 선택·점수 규칙과 테스트 서버의 실험용 선택 규칙은 여전히 다르다.

## 해석과 추가 검증

영상은 한 참가자의 제한된 표본으로, 프레임별 동작 시작·종료 정답이 없다. 박수 영상의 준비·이행 구간에서는 손 들기 후보가 나타날 수 있다. 박수 감지는 손목 거리 기반의 단일 이벤트이며 손바닥 접촉을 직접 확인하지 않는다. 손목·검지가 가려지거나 화면 밖으로 나가면 손 들기를 놓칠 수 있고, 검지 조건 완화로 오인식이 늘 수 있다. 화면 각도 0도·30도, 다른 참가자와 Temi 카메라에서 별도로 검증해야 한다.

현재 CSV는 프레임 단위이므로 참가자·실제 동작·시행별 정답을 별도로 연결해야 한다. `no_action`, `pose_not_detected`, `conflict`를 누락하지 않고 시행 기준을 정해 정확도와 혼동행렬을 계산한다. 제공 영상의 좌우 반전 여부와 파일명 혼동도 정답 지정 전에 확인한다.
